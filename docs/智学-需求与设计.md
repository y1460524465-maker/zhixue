# 智学 · 需求与设计

本文是这套系统的需求说明 + 设计决策记录。
整体架构图见 [`docs/images/zhixue-architecture.png`](images/zhixue-architecture.png)。

---

## 一、需求概要

### 1.1 四个 Agent 的职责

| Agent | 面向 | 输入 | 输出 | 明确不做 |
|---|---|---|---|---|
| **教案生成** | 知识 | 一个主题 / 知识点 | 教案、讲义、学习计划（.docx） | 不产生题目，不关心某个学生学得怎样 |
| **出题** | 要练什么 | 知识点 **或** 错题 | 一套题（作业 / 试卷） | 不批改，不保管学情数据 |
| **作业批改** | 学生的作答 | 答题卡或逐题作答 | 分数 + 逐题对错 + 评语；并把错题推给学情 | 不做学情结论，不出题 |
| **学情分析** | 数据事实 | 批改推来的错题；查询请求 | 错题清单（对外）+ 学情画像/薄弱点/趋势（对内） | 不决定"出哪几道题"，不直接批改 |

### 1.2 边界约定

三条明确划定的边界：

1. **教案 Agent 不进闭环。** 它面向知识不面向人，是一条独立的生产线，
   不参与"做错 → 记下 → 再练"的循环。
2. **出题只有一个错题入口，不分"重做原题"和"找相似题"。**
   从错题出发就是一条路：取错题指针 → 换实体 → 出题。
3. **学情分析保留自己的分析产出**（画像、薄弱点、趋势、班级对比），
   但**对出题 Agent 只交事实**——错题清单，不含结论、不含排序建议。

## 二、出题的两条入口

### 2.1 标签式（用户直接说知识点）

```
用户："给 Python 装饰器出 3 道题"
  -> 解析知识点（把"装饰器"对上"函数与装饰器"）
  -> 题库结构化筛选（kp_id / 题型 / 难度）
  -> 题库语义检索（作为相似题参考展示）
  -> 落成作业或导出试卷
```

### 2.2 样本式（从错题出发）

```
用户："把做错的题再出几道给我练"
  -> 出题 Agent 通过 A2A 找学情 Agent 要错题【指针】
       （q_id / kp_id / 错次 / 掌握度，不含题干）
  -> 出题 Agent 拿指针回【自己的题库】换实体（题干、选项、答案）
  -> 用交互记忆排除最近出过的题
  -> 落成作业，并把这次出的题写进交互记忆
```

### 2.3 为什么"错题"比"用户贴题"更干净

这是本设计里最关键的一个判断。

| | 用户贴的题 | 系统里的错题 |
|---|---|---|
| 题干原文 | 要从一段话里切出来 | 现成的，在题库里 |
| 知识点 | 模型猜 | **现成的 kp_id** |
| 题型、难度 | 模型猜 | **现成的字段** |
| 猜错的风险 | 有 | **零** |

错题是**系统自己批改出来的样本**，所以标签和原文都是系统自己产生的，
join 一下就全有了。不需要归一化、不需要模型推断、也不会编造出题库里不存在的知识点。

> 换句话说：用户贴题那条路需要"猜"，错题这条路只需要"查"。
> 所以先用错题入口，用户贴题可以以后复用同一套基础设施。

## 三、协作规矩

### 3.1 数据归谁管，就通过谁拿

这是整套系统最重要的一条架构规矩。它保证每个数据只有一个出口，
不会出现"两个 Agent 各有一套实现、结果还不一致"。

**错题记录库归学情 Agent 独占**：

* 批改 Agent 要写 → 通过 A2A 调 `action=write_mistakes`
* 出题 Agent 要读 → 通过 A2A 调 `action=list_mistakes`
* 谁都不直接连那张表

**题库归出题 Agent**：所以"指针换实体"这一步是出题 Agent 自己的活，
不需要别人帮忙。

### 3.2 三条协作链路

| 链路 | 类型 | 现状 |
|---|---|---|
| 主应用 → Agent | 纵向编排 | 已实现 |
| 批改 → 学情（写错题） | 横向通知 | 已实现，走真实 A2A 消息 |
| 出题 ← 学情（读错题） | 横向读取 | 已实现 |

横向调用**都带降级**：A2A 走不通就在本地直连同一套工具，
并在返回值里标明走的是 `a2a` 还是 `local`。衔接如果是硬依赖，它就是个脆弱点。

## 四、用户隔离与记忆

### 4.1 两种身份要分开

| | 是什么 | 例子 |
|---|---|---|
| **账号身份** user_id | 谁在对话 | US00001 |
| **数据主体** student_id | 对话里谈的是谁的数据 | S00001 |

学生自用的时候两者重合；老师用的时候完全不重合——一个账号会去查几十个学生。

所以**结构上现在就分开**：学生账号强制绑定自己的学号（请求里传什么都改不了），
老师账号不绑定，谈谁由对话内容决定。

### 4.2 隔离落在每一层

只在一层做隔离必然漏，所以每层都带身份：

| 层 | 隔离方式 |
|---|---|
| 入口 | 身份只从 Authorization 头解析，**不从请求参数取** |
| 会话 | `conversation` 按 user_id 过滤；别人的 session_id 读不到内容 |
| 草稿 | key = `zhixue:draft:{user_id}:{session_id}` |
| 文件 | `data/outputs/{user_id}/`、`data/uploads/{user_id}/` |
| 跨 Agent | user_id 随 TaskRequest 一路传递 |

### 4.3 记忆分四层

| 层 | 记什么 | 归属 | 用途 |
|---|---|---|---|
| 会话记忆 | 最近聊了什么 | 主应用 | 多轮上下文 |
| 工作态记忆 | 槽位草稿（"还差一个知识点"） | 主应用 | 多轮补槽 |
| 业务记忆 | 错题、成绩、薄弱点 | 学情 Agent | 学情分析 / 错题出题 |
| 交互记忆 | 出过哪些题 | 出题 Agent | **防重复** |

第四层最容易被忽略，但它有明确的功能价值：
**"这个学生最近出过哪几道题"记下来，下次出题直接排除——不用算法，靠记忆就解决了重复出题的问题。**

### 4.4 三条硬约定

1. 身份在入口解析一次，之后**随任务包传递**，任何一层都不重新解析；
2. 所有存储访问**强制带身份过滤**——不允许"不带身份的全表查询"存在；
3. **身份缺失或非法直接拒绝**，不给默认值。

> 第 3 条最容易被违反：为了"方便调试"给缺身份的情况留个默认用户，
> 这个默认值就成了漏洞。**降级可以用于功能，不能用于权限。**

### 4.5 Agent 必须无状态

Agent 是常驻服务，四个用户同时来用的是同一个进程。
如果把"这个用户聊到哪了"存在 Agent 的内存变量里，并发时数据必然串——
而且串得很隐蔽，压测都未必压得出来。

所以：**记忆是"每次去取"，不是"进程里存"。** 用完就丢。

## 五、关键设计决策与取舍

| 决策 | 理由 | 代价 |
|---|---|---|
| Agent 无状态，记忆外置 | 并发不串、重启不丢、可水平扩展 | 每轮多一次存储读取 |
| 身份随任务包传递，不从全局取 | 分布式环境下唯一可靠的隔离方式 | 调用链上每个函数都要显式带参 |
| 跨 Agent 调用都带降级 | 单点故障不断链 | 每个调用点都要自己写降级逻辑 |
| 错题只传"指针 + 统计" | 职责清晰；题干归题库，不重复存 | 出题侧多一次"换实体" |
| 防重复用记忆而非算法 | 简单、可解释、零成本 | 换设备时记忆不共享（本设计不需要） |
| 出题入口二不分"重做/相似" | 少一层判断，用户不用选 | 决策粒度变粗 |
| 教案不进闭环 | 职责单一，演化互不影响 | 少了"针对薄弱点出讲义"的玩法 |

## 六、现状与已知边界

诚实记录，避免误读：

1. **向量库尚未建立。** 课本库与题库都只有 MySQL 里的结构化数据，
   Milvus 集合还没建（建索引的入口只定义了、没有被调用）。
   当前检索实际走的是 **BM25 关键词降级**，结果里标 `backend=keyword`。
2. **入口一的语义检索结果只作参考展示**，不参与选题；
   真正决定出什么题的仍是结构化筛选。
3. **题库规模小（46 道题）、知识点只有 19 个**，
   同一知识点下常常只有 2~3 道题，"相似题"的可选空间有限。
   这类能力只有在题库上千道时才能体现价值。
4. **难度是人工标注的 1~3 级**，标注不准时"同难度"就是假的。
5. **教案模板里的"错题报告"目前没有 Agent 使用**，定义了但未接线。
6. **没有密码找回、轮换、多设备登出**；令牌是自签的，适合内部演示，
   生产环境需要换成正规的身份服务。
7. **语料是内置的模拟内容**，系统只接了"读"的口，
   没有"外部资料解析入库"的流水线。

## 七、演进阶段

| 阶段 | 内容 | 前置依赖 |
|---|---|---|
| 一 | 账号体系、用户隔离、四层记忆 | 无 |
| 二 | 学情开放"读错题"接口 + 出题错题入口 | 无 |
| 三 | 建立向量库，让语义检索真正参与选题 | Milvus + 嵌入模型 |
| 四 | 用户贴题入口（复用阶段三的基础设施） | 阶段三 |
| 五 | 外部资料解析入库流水线（PDF/Word/PPT/OCR + 分段） | 无 |
| 六 | 难度标注治理、题库扩容 | 教研投入 |

前两个阶段已完成，见仓库代码。
